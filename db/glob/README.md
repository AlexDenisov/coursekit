# db/glob: Glob matching

> **Summary.** `KEYS user:*`, `SCAN 0 MATCH h?llo` and `PSUBSCRIBE news.[ab]*`
> all use one matcher, `stringmatchlen` in Redis's `util.c`. `db/generic` and
> `msg/pubsub` call yours. The surprising part: the obvious recursive matcher
> is exponential, and one `KEYS` with a hostile pattern freezes a
> single-threaded server.
>
> **Before:** nothing. **Next:** `db/generic`, `msg/pubsub`.

## The rules

| Pattern | Matches |
|---|---|
| `h?llo` | hello, hallo; not hllo |
| `h*llo` | hllo, heeeello |
| `h[ae]llo` | hello, hallo; not hillo |
| `h[^e]llo` | hallo, hbllo; not hello |
| `h[a-b]llo` | hallo, hbllo |
| `a\*c` | only `a*c` |

Walk the pattern and the string side by side. A literal byte or `?` consumes
one byte of each. A set `[...]` reads up to its `]` and consumes one string
byte if it matched. `*` is the interesting one: it may swallow any number of
bytes, so you try the rest of the pattern against each remaining suffix of the
string.

## Redis's quirks

The tests compare you against real Redis on 390 patterns × 36 strings
(`Glob.MatchesRedisOnEveryCase`, generated by `tools/glob_reference.py`), so
the corners count:

```
a[b      matches "ab"      a set with no ']' ends at the end of the pattern
[]       matches nothing   ']' right after '[' closes an empty set
[^]      matches any byte  ...and its negation
a[a-]    matches "a^"      "a-]" is read as a range from ']' to 'a', which contains '^'
*        not ""            the matcher stops as soon as the string is used up;
                           KEYS * returns the empty key only via a fast path
                           that skips matching (you'll add it in db/generic)
```

When in doubt, port the logic of `stringmatchlen` from Redis's `src/util.c`, or
ask the oracle: add the pattern to `FIXED` in `tools/glob_reference.py`.

## The pitfall: exponential backtracking

`a*a*a*...a*b` (25 stars) against 60 `a`s has no match. A naive matcher tries
every way of splitting the 60 bytes among the 25 stars, about 10^17 ways.

The fix Redis uses (since 7.0) is one flag. Suppose the rest of the pattern,
after some `*`, fails against *every* suffix of the string. Then giving an
*earlier* star a longer match can't help: that only leaves a shorter suffix for
the same rest. So the first such total failure ends the whole search.
`Glob.ManyStarsDoNotBacktrackExponentially` checks that you answer in well
under a second.

## API

| Function | Contract |
|---|---|
| `glob_match(pattern, s)` | the rules above; binary safe; O(\|pattern\| · \|s\|) |
